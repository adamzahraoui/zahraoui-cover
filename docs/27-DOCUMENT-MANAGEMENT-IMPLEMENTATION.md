# 27 — Centralized document management

Staff open **Documents** from the administration menu. The inventory shows the total number of document records and the total bytes registered in PostgreSQL, including archived files. The counters describe the whole inventory. The result count below the list reflects the current filters. The volume is calculated from stored metadata and does not scan the filesystem.

## Use the document list

- Search by original filename, customer name, quote reference or contract reference. Filter by category, processing status, archival status and creation date. Dates use Africa/Casablanca and include both selected calendar days.
- Open a document's name to see its category, original or generated name, version, size, dates, associated records and recent activity. Customer, quote and contract links open the matching staff records. Those pages, quote revisions and contract renewal entries link back with the relevant filter selected.
- Choose **Aperçu PDF** to open a ready, system-generated quote in a separate tab. Uploaded PDFs use **Télécharger**. Both actions require a valid staff session and verify the file before returning it.
- During local testing, select **Ajouter un PDF**, find the contract by reference, policy number or customer, then choose an approved category and a PDF up to 4 MiB. A link from a contract preselects that record. A link from a customer restricts the contract picker. Add only approved business documents and exclude identity documents and medical records.
- An administrator can archive a ready supporting or other approved document. It moves out of the default list and remains available under **Archivés**, with its original file, links and audit history. Issued proposals and insurer policies stay in the current dossier.

## Categories and relationships

| Category | Association and behavior |
| --- | --- |
| `QUOTE_PDF` | Generated by the existing quote worker. The row points to the exact quote revision and records the quote version frozen during issuance. It supports preview and download. |
| `CONTRACT_PDF` | Insurer policy attachment. The row points to one contract and accepts attachment downloads. |
| `CONTRACT_SUPPORT` | Approved supporting contract attachment. Eligible for archival. |
| `BUSINESS_PDF` | Other approved contract-related business PDF. Eligible for archival. |

A document has one quote or one contract as its parent. The customer is identified through that parent, so the document cannot carry a conflicting customer association. The central uploader checks a supplied customer ID against the contract and refuses quote IDs and generated quote kinds. Uploads are additive. Each contract has a shared sequence of up to 100 attachments across all categories, including historical and archived files. Existing quote and policy metadata and checksums remain in the same table.

Migration `20261127060000_document_management` adds two category values, an optional original display name, an optional staff uploader, an optional archived timestamp, a document version and inventory indexes. Old rows start at version 1 and keep their dates, file keys, byte counts, checksums and parent IDs. PostgreSQL blocks archiving primary records.

## API and permissions

| Method and path | Permission and result |
| --- | --- |
| `GET /api/admin/documents` | Staff. Returns a page with `data`, `meta`, `storage` and `uploadEnabled`. Supports `q`, `kind`, `status`, `archived`, `clientId`, `quoteId`, `contractId`, `from`, `to`, `page` and `limit`. The default excludes archived rows. Use `archived=true` for archived rows and `all` for both. |
| `GET /api/admin/documents/:id` | Staff. Returns a metadata record and recent audited activity without filesystem keys or digests. |
| `POST /api/admin/documents` | Staff in local testing. Send raw `application/pdf`, a percent-encoded `X-Document-Filename` header, and query parameters `contractId`, `version` (contract version), `kind` and optional `clientId`. Returns the document detail with 201. |
| `POST /api/admin/documents/:id/archive` | Admin. Send the current document `version`. Returns updated detail. |
| `GET /api/admin/documents/:id/download` | Staff. Returns a ready PDF after verifying SHA-256 and byte length. Use `inline=true` only for a generated quote. Filenames on downloads use the business reference and attachment sequence. |
| `POST /api/admin/contracts/:id/documents` | Existing local insurer attachment endpoint. It now uses the same storage, duplicate checks and upload limit. The original raw request shape remains supported. The current browser also sends a filename for validation. |

Staff mutations require the same-origin check and session CSRF token. Uploads allow 30 attempts per staff account per 15 minutes, shared with the contract upload endpoint. The server audits metadata reads, file reads, uploads and archival without recording filenames, content or storage paths in event metadata. Quote generations write document activity. No staff endpoint deletes documents.

## Private storage and failures

1. The server validates the filename extension, MIME type, 4 MiB limit, PDF header, classic cross-reference table and end marker. It rejects supported detectable active features, encrypted files and compressed object containers. This narrow parser can reject legitimate PDFs. Malware scanning is still required before production uploads and untrusted PDFs are attachment-only.
2. The server locks the contract, confirms its version and upload eligibility, then checks for duplicate bytes in the same contract and category. It stores the file using a fresh UUID filename inside the existing `QUOTE_PDF_DIR`. The directory must be a canonical absolute path outside the repository, owned by the service, with no group or public permissions.
3. The same file helper used for quote generation writes a private temporary file, synchronizes it and publishes without overwriting an existing file. The database transaction records the PDF's SHA-256 digest, byte count, metadata and audit entries. It advances the contract version once. Interrupted request bodies never reach the storage step.
4. On failure the service attempts to remove the newly written file only after checking that its database row did not commit. If the database is unavailable or cleanup fails, the service leaves the file for review and records a technical document ID. Read failures for missing or corrupt files return a redacted error. File opening rejects symbolic links, unexpected file types, invalid keys and nonprivate permissions.
5. To identify orphan candidates, an authorized operator can compare UUID filenames from the private directory against `documents.storage_key` and active quote-generation jobs during a quiet maintenance window. Compare matching database and storage backups, account for in-flight files and record technical identifiers only. Review results before any manual retention decision. B11 adds no automatic cleanup.

The existing local-only quote, upload and private PDF storage gates remain in force. Production needs approved malware scanning, approved document-handling and retention policy, and private durable storage. Existing issuance and SMTP conditions still apply. A future spreadsheet import should use its own CSV/XLSX validation, temporary storage and lifecycle. The business document endpoints accept PDFs only.

## Verification

- Frontend and backend TypeScript, ESLint and production builds passed. Prisma validated the schema, all eight migrations applied on an isolated fresh database and schema comparison found no drift. An isolated B10-to-B11 upgrade preserved both existing documents, their exact bytes, their relationships and frozen metadata.
- All 6 unit tests and 53 PostgreSQL integration tests passed, including 44 prior tests and nine [B11 cases](../backend/tests/documents.integration.ts). They cover authenticated reads, metadata and inventory, search and pagination, association and upload validation, stale requests, duplicates, archival restrictions, restricted PDF previews, audit history, missing and tampered files, database rollback and filesystem failure, interrupted uploads, throttling and the production upload gate.
- Chrome passed at **390, 768, 1024 and 1440 px**. Staff navigated through the sidebar, searched and filtered existing quote and policy PDFs, opened customer and contract records, uploaded and downloaded a new policy, archived a supporting document and confirmed it remained available after refresh. Anonymous access was rejected and historical PDFs matched byte for byte. The tested layouts had no horizontal overflow or uncaught browser exceptions.
